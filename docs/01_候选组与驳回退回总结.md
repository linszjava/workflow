# 候选组与驳回退回改造总结

为了实现企业级工作流中常见的**候选组（抢占式审批）**与**驳回退回修改**功能，我们对系统的前后端进行了以下针对性改造：

## 一、 后端改造

### 1. BPMN 流程引擎配置 (`leave-process.bpmn20.xml`)
- **引入候选组**：将部门经理和 HR 节点的固定审批人（`assignee`）替换为候选组（`flowable:candidateGroups`），使得同组的多个用户都可以看到该任务。
- **新增退回节点**：增加了一个名为「申请人修改」的 UserTask（`modifyTask`），其处理人动态绑定为流程发起人（`flowable:assignee="${initiator}"`）。
- **优化网关逻辑**：在经理和 HR 节点后增加排他网关。当点击驳回（`approved==false`）时，流程不再直接结束，而是流转到「申请人修改」节点。在修改节点后增加网关，根据用户选择决定是重新提交（流回到经理审批）还是撤回（结束流程）。

### 2. 用户与候选组初始化 (`FlowableIdentityConfig.java`)
- 新增了启动时自动执行的配置类。
- 初始化了模拟用户：`zhangsan` (员工), `manager` (经理), `manager2` (副经理), `hr` (人事)。
- 初始化了候选组：`deptManager` (部门经理组), `hrGroup` (HR组)。
- 将用户与对应候选组进行绑定关联，建立起 Flowable 的 Identity 数据，为后续的候选任务查询提供基础支撑。

### 3. 核心业务服务改造 (`LeaveService.java`)
- **发起流程绑定**: 在 `submitLeave` 时，通过 `identityService.setAuthenticatedUserId(leave.getUserId())` 绑定发起人，供 `${initiator}` 表达式使用。
- **认领与取消认领**: 新增了 `claimTask` 和 `unclaimTask` 方法。候选组任务需要先认领才能变成个人任务进行审批。
- **多维度任务查询**: 改造了 `getTasksForUser`，将 **待认领任务**（通过 `taskCandidateUser` 查询）和 **已认领任务**（通过 `taskAssignee` 查询）合并返回，并附加 `taskStatus` 标识。
- **驳回逻辑修改**: 在 `reject` 时不再直接结束，而是将业务表状态变更为 `3`(已驳回)，供申请人修改。
- **修改后操作**: 新增了 `resubmit`（重新提交并恢复状态为 `1`）和 `withdraw`（撤回并变更状态为 `4`）的逻辑。

### 4. 接口层暴露 (`LeaveController.java`)
- 新增了相关 RESTful 接口：`/tasks/{taskId}/claim`、`/tasks/{taskId}/unclaim`、`/tasks/{taskId}/resubmit`、`/tasks/{taskId}/withdraw`。

---

## 二、 前端改造

### 1. 完善 API 定义 (`api/index.ts`)
- 扩充了与后端对应的新接口映射函数：`claimTask`, `unclaimTask`, `resubmitTask`, `withdrawTask`。

### 2. 模拟多角色竞争 (`App.vue`)
- 在顶部的用户切换下拉框中，新增了 `赵副经理` (manager2) 角色。
- 用于演示 manager 和 manager2 两人同属 `deptManager` 组时，看到同一条待办并竞争认领的场景。

### 3. 待办与审批中心重构 (`MyTasks.vue`)
- **任务状态区分**: 列表中增加了状态列，通过不同颜色的 Tag 区分「待认领」(橙色) 和「已认领」(绿色)。针对退回的节点（`modifyTask`）标题标红处理。
- **操作按钮动态化**:
  - 对于「待认领」任务，仅显示「认领」按钮。
  - 对于「已认领」任务，显示「审批」和「退回」(取消认领) 按钮。
  - 对于「申请人修改」任务，显示「处理」按钮。
- **新增修改操作弹窗**: 为流程被驳回至申请人时，提供了一个独立的对话框，允许申请人重新填写事由，并选择「撤回申请」或「重新提交」。
