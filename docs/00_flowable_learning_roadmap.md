# Flowable 工作流引擎学习路线图

这份文档整理了本项目目前已经掌握的 Flowable 技术核心栈，以及为了应对更复杂的企业级业务场景，后续还需要逐步攻克的知识点。

---

## 🟢 一、 已学内容（基础与核心主线）

这些内容构成了当前“企业级请假审批系统”的基石。

### 1. BPMN 基础组件
* **启动事件 (`startEvent`)**: 流程如何开始。
* **结束事件 (`endEvent`)**: 流程如何正常结束。
* **用户任务 (`userTask`)**: 需要人去干预处理的节点，审批系统的绝对主角。
* **顺序流 (`sequenceFlow`)**: 节点与节点之间的流转方向（有向箭头）。

### 2. 审批人指派策略
* **固定分配 (`assignee`)**: 指定给具体哪一个人审批（如：`manager`）。
* **动态分配 (UEL 表达式)**: 利用像 `${initiator}` 这样的表达式，在运行时动态把任务分配给流程的发起人。
* **候选组抢占 (`candidateGroups`)**: 任务指派给一个部门/组（如：`deptManager`），组内多人均可看到，谁先**认领（Claim）**，任务就是谁的。支持**取消认领（Unclaim）**。

### 3. 网关与条件分支
* **排他网关 (`exclusiveGateway`)**: 类似代码中的 `if-else`。引擎会评估网关后连线上的条件（`conditionExpression`），并且**只走第一个符合条件的分支**。
* **流程变量控制流转 (`variables`)**: 如利用 `variables.put("approved", true)` 或 `false`，再由排他网关判断 `${approved == true}` 来决定是过审还是驳回。

### 4. 驳回与循环退回
* **驳回退回机制**: 不使用网关直接结束流程，而是流转到一个特殊的 UserTask（`modifyTask`），指派给申请人。
* **循环执行**: 在申请人修改完毕后，依靠条件判断（如：`resubmit == true`）重新指向之前的审批节点（如经理审批），形成业务循环闭环。

### 5. API 与应用集成实践 
* **BusinessKey（核心）**: 把业务表的主键（如：`biz_leave` 的 id）与流程实例进行绑定，实行业务与工作流状态分离的架构设计。
* **自动化建表与部署**: Spring Boot 启动时结合 MyBatis-Plus 自动建表，并且自动加载和发布 `resources/processes/` 下的 `.bpmn20.xml` 配置文件。
* **流程轨迹与历史 (`HistoryService`)**: 查询已完成的活动（`HistoricActivityInstance`），并且在前端进行脱离纯网关层面的可视化呈现（过滤杂音，预测未来节点）。

## 🔴 二、 待学内容（企业级进阶场景）

当面临大厂或复杂政务审批需求时，需逐步补齐这部分能力。

### 1. 复杂流转组件（必须拿下）
* [ ] **并行网关 (`parallelGateway`)**: 相当于多线程。一份单据分抄给“财务部”和“法务部”同时进行审批，**必须两边都通过后**才汇聚进入下一步流程。
* [ ] **多实例/会签 (`MultiInstanceLoopCharacteristics`)**: 
   * 同一个节点要分配给N个人。例如一票否决、多数通过、按比例通过（比如：5位专家评委打分，其中至少3人通过即算通过）。
   * 分为并行型会签和串行型会签。

### 2. 人事委托与智能指派
* [ ] **任务委派 (`Delegate`) 与 转办 (`Transfer`)**: 李经理突然要休产假，她把目前手头的审批任务直接丢给王副经理“代办”。
* [ ] **监听器 (`TaskListener / ExecutionListener`)**: 大杀器，目前我们的候选人还是在 XML 里或者启动类写死的。利用监听器，当流程流转到“部门经理审批”的那一瞬间触发后端 Java 代码，去公司的 LDAP 或组织架构数据库里查**当前申请人的真实直属上级**，然后把权限精准赋给他。

### 3. 定时与自动化
* [x] **定时边界事件 (`timerBoundaryEvent`)**: 附加在任务身上的倒计时。比如“经理任务如果24小时无人审批”，就超时触发走另外一条线发送催办邮件，或者自动走高管加急通道。
* [x] **服务任务 (`serviceTask`)**: 不需要人审批的节点，引擎纯自动调用后端的一个 Java Service 或者发 HTTP 请求（例如审批完成后，最后一环自动触发服务去下发工资单）。

### 4. 高级子级联动
* [x] **子流程 (`subProcess` / `callActivity`)**: 主流程太庞大，我们可以抽离出一个子流程。比如“员工请假大于10天的，不管目前卡在哪里，都要外挂调起一套专门的老板加签子流程”，主流程挂起等待。

### 5. 前端可视化与低代码相关
* [ ] **引入 `bpmn-js` 前端组件**: 不再依赖硬编码拼接预测步骤，前端能够根据 XML 解析实时连线着色图。
* [ ] **流程动态部署**: 不再是 XML 文件硬绑定在后端 jar 包里，而是可以直接在页面画完图，通过 HTTP 提交动态产生新的流程版本（版本控制管理）。
